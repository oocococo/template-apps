# 知己产品设计

## 1. 产品定义

知己是一款服务个人自然月经周期的记录与知识陪伴网页应用。用户记录实际发生的事，应用计算个人规律、估计接下来的日期，并通过适合当下的知识文字提供陪伴。

产品围绕四个问题组织：

1. 今天身体有什么感受，发生了什么？
2. 我现在可能处于周期的什么位置，接下来会怎样变化？
3. 下一次月经大概什么时候开始？
4. 最近的周期和身体状态有哪些变化？

陪伴的载体是今日文字、生活建议和可展开的知识卡片。内容来自随应用发布的知识资料，由日期、记录及计算结果选择。

### 1.1 运行方式

- Tiana Web 托管静态前端应用。
- Tiana DB（SQLite）保存个人原始记录、预测快照及必要设置。
- 浏览器通过 Tiana 运行时鉴权及官方 SDK 直接读写数据库。
- 统计、概率计算、阶段估计和知识选择全部在浏览器执行。
- 每个应用服务一个使用者，同一 Tiana 身份在手机与桌面访问同一份云端数据。
- 日期按本地日历日期记录；写入时间按时间戳保存，两者用途分开。

### 1.2 完整版范围

首次发布包含：经期日历、每日记录、漏记处理、月经开始预测、经期结束估计、排卵及易孕窗口估计、周期阶段估计、个人统计与变化观察、知识陪伴、平均预测误差、数据导入导出。

所有功能围绕自然月经周期设计。

## 2. 产品原则

- **用户记录事实，程序决定计算方式。** 用户填写日期、感受和是否漏记，不选择用于预测的样本。
- **日历是记录入口。** 开始、结束、补录和修改经期均围绕选定日期或日期范围进行。
- **记录与估计分开。** 已记录经期使用实色，预测窗口使用虚线或浅色，阶段名称注明是否估计。
- **空白保持空白。** 未记录不等于无出血、无症状或没有发生事件。
- **变化基于个人历史。** 解读给出时间范围和数据依据，不用群体平均替代个人事实。
- **陪伴先于成绩。** 首页关注当下感受和照顾自己的建议；预测表现只提供平均预测误差。
- **事实修改自动生效。** 保存后自动重算相关结果，用户只需确认记录已保存。

## 3. 功能清单

| 模块 | 功能 | 用户获得的结果 |
|---|---|---|
| 经期日历 | 开始、结束、日期范围补录、修改和删除 | 清楚的实际经期历史 |
| 出血事实 | 区分月经、点滴出血和不确定出血 | 保留事实，避免误重置周期 |
| 漏记 | 此次月经之前有漏记／没有漏记 | 跨断点间隔不会污染预测 |
| 每日状态 | 出血量、颜色、疼痛、症状、情绪、睡眠、便便、爱爱、白带、备注 | 低负担的身体记录 |
| 月经预测 | 中心日期、固定 7 天窗口、估计概率 | 对下一次月经有准备 |
| 经期结束 | 个人历史持续时间中位数估计 | 当前或下次经期大概何时结束 |
| 阶段估计 | 月经期、卵泡期、排卵附近、黄体期 | 理解可能的身体变化 |
| 排卵与易孕 | 估计排卵日期、示意窗口、日历相对可能性 | 理解日期推算的不确定性 |
| 逾期核实 | 补录入口、明确确认截至某日尚未来经 | 获得真实新信息后再更新预测 |
| 统计与观察 | 周期、持续天数、出血及每日状态趋势 | 看见自己的变化 |
| 知识陪伴 | 今日文字、生活建议、展开／收起知识卡片 | 当下可读、可执行的陪伴 |
| 预测表现 | 平均预测误差 | 简单了解个人日期估计的偏差 |
| 数据管理 | JSON 备份导出、JSON 导入、CSV 记录导出、删除个人数据 | 保留和管理自己的记录 |
| 响应式使用 | 手机底部导航、桌面侧栏、云端持久化 | 在不同屏幕持续使用 |

## 4. 信息架构与页面

主导航为「今天」「日历」「观察」「我的」，使用哈希路由，刷新后恢复当前页面。

### 4.1 今天

按以下顺序组织：

1. **今日概览**：日期、周期第几天、已记录经期或估计阶段。
2. **陪伴文字**：一段主文案与一至两条建议。
3. **快捷记录**：记录今天；经期开始／结束操作打开当天日历记录面板。
4. **下次月经**：预计开始日期、固定 7 天窗口、可用时的统计估计概率。
5. **相关知识卡片**：以问题或主题为标题，点击展开正文，再次点击收起。

经期进行中时优先展示经期第几天和预计结束；记录不足时优先提示如何开始记录。预测窗口已过时显示核实入口。首页使用少量文字，不堆叠统计图表。

阶段展示示例：

- 「已记录：月经第 3 天」。
- 「周期第 20 天 · 可能处于黄体期」。
- 「当前阶段暂不能确定」，同时仍可阅读一般身体照护内容。

### 4.2 日历

手机采用月历加日期详情；桌面采用月历和详情并排。

日历包含：

- 实际经期的连续区间。
- 下次月经估计窗口及中心日期。
- 估计排卵附近和易孕窗口的浅色标记。
- 当天记录的小图标或数量提示。
- 今天和选中日期的独立标记。

图例以文字解释实测和估计；颜色之外还使用边框、纹理或图标区分。

点击一天打开详情。选择日期范围可补录完整经期。详情内编辑当日状态、出血性质、经期开始或结束。预测日期不能直接变成实际记录，必须由用户确认真实日期。

### 4.3 观察

三个内容区：

- **周期**：平均周期、波动水平、周期长度趋势、经期持续时间。
- **身体记录**：出血量和颜色、疼痛、症状、情绪、睡眠、便便、爱爱、白带。
- **个人观察**：基于足够数据的变化文字及来源记录。

提供「最近 3 次」「最近 6 次」「最近 12 次」周期范围；每日状态另外提供最近 30／90 天。按实际数据启用范围，空状态给出记录入口。

平均预测误差放在周期区域的次要位置，文案如「已核实的 6 次预测，平均相差 2.3 天」。核实次数是样本说明，不作为另一项成绩展示。

### 4.4 我的

- 数据导入与导出。
- 个人数据删除。
- 每日记录项目的显示偏好。
- 知识目录、来源及健康说明。
- 应用及算法版本。

记录偏好只控制表单显示，隐藏项目不删除已有记录。

### 4.5 视觉与可访问性

采用温和、清晰的配色和有留白的卡片；关键信息优先于装饰。手机常用按钮便于单手点击，触控目标至少 44×44 CSS 像素。桌面扩大图表和日历空间，不改变业务规则。

知识卡片标题可通过键盘操作，并提供展开状态。表单字段有明确标签；错误信息贴近输入项。尊重系统减少动画设置。疼痛、情绪和出血等级同时使用文字和图形，避免仅靠颜色表达。

## 5. 经期与每日记录交互

### 5.1 经期录入

经期是一段开始日期至结束日期的日历区间，结束日期可为空，表示尚未记录结束。

- 开始：选择真实开始日，保存一条进行中的经期。
- 结束：选择最后一天有月经出血的日期，闭合该区间。
- 补录：选择开始和结束日期，可附备注和是否漏记。
- 编辑：修改日期、备注或漏记事实，保存后自动更新日历、统计和预测。
- 删除：确认删除该次经期；保留同一天独立填写的身体记录，重新核实其出血性质。

观察记录不能填写未来日期。预测可落在未来，但不会写入原始记录。

### 5.2 唯一性与不重叠

业务模型和数据库共同保证：

- 经期开始日期唯一。
- 完整经期之间不能重叠，起止日均包含在区间内。
- 同时最多一条结束未知的经期，且必须是日期顺序中的最后一条。
- 新增另一条经期前，需要先补充已有进行中经期的结束日期。
- 日期修改、历史补录和导入遵守相同约束。

重叠操作保留用户输入，指出冲突日期，允许修改原记录或调整新范围。系统不猜测前一次经期结束日期，也不自动合并不同经期。

### 5.3 出血性质

已确认自然月经通过经期区间记录。经期外的出血可在当天记录为「点滴出血」或「不确定」。用户之后确认属于月经时，需补充经期区间，相关当日性质同步调整。

点滴出血不会作为周期起点。不确定出血位于两次经期之间时，该间隔暂不用于预测；用户确认性质后自动重算。

### 5.4 漏记

字段为「此次月经之前是否漏记」，值只有有／没有，表单默认没有，用户可按事实修改。它描述本次与上一次月经之间的记录连续性。

首条记录没有前一次可比较记录，该字段不产生周期观测。历史间隔明显不同于以往时，以非阻断提示询问「期间是否有月经未记录？」；用户回答有或没有，也可以关闭提示，原事实不被系统修改。

- 选择有：只排除跨越漏记的间隔，本次仍能作为下次周期起点。
- 选择没有：保留真实间隔，无论它比历史长或短多少。
- 关闭提示：继续采用当前保存的漏记值，没有额外的待确认漏记状态。

补录会改变记录之间的关系：若拆分原本标记有漏记的间隔，保存时分别询问新形成的间隔是否仍有漏记。删除中间经期使剩余间隔缺少一次已知月经时，将后继记录标为有漏记；若删除原因是原记录并非月经，由用户确认新的连续性事实。两种操作都在同一保存动作中完成。

### 5.5 每日字段

所有项目可选，未填写值为空。再次打开同一天编辑现有记录，不新增第二份日记录。

| 项目 | 首发字段 | 统计口径 |
|---|---|---|
| 出血 | 性质、量：无／少／中／多；颜色：粉红／鲜红／暗红／褐色／其他，可多选 | 主观等级天数、颜色类别频次 |
| 疼痛 | 程度 0～10、位置 | 已记录日的自评分及分布 |
| 身体感受 | 腹胀、乳房胀痛、头痛、疲劳、腰酸等多选 | 已填写日中的出现频率 |
| 情绪 | 平静、愉快、低落、焦虑、易怒等多选 | 已填写日中的类别频率 |
| 睡眠 | 时长、质量：差／一般／好 | 有记录日的时长与质量趋势 |
| 便便 | 当天各次排便；每次可填 Bristol 1～7 型、费力、疼痛及备注；可明确选择当天没有 | 次数、便型分布、相关感受 |
| 爱爱 | 当天各次事件；可填是否采取保护措施、疼痛／不适、事后出血、备注；可明确选择当天没有 | 已记录事件次数、不适记录 |
| 白带 | 无／有；有时可填量、颜色、质地、明显异味、瘙痒／灼热 | 类别及症状变化 |
| 备注 | 自由文字 | 日期时间线展示 |

便便、爱爱采用事件列表：未填为未知，空列表代表用户明确记录当天没有，每个列表项代表一次事件。没有填写具体便型也可以只记录一次排便。爱爱记录不要求伴侣身份，不推算怀孕概率。

白带建议颜色项为透明、乳白、偏黄、偏绿、带血、其他；质地为稀薄、水样、黏稠、可拉丝、块状、其他。颜色和质地均是用户观察类别，支持同时记录多项。

若每日出血性质与经期范围冲突，保存时请用户确认事实并相应修改区间或当日分类。例如删除经期后，不能留下没有所属经期的「月经」日记录。经期中可记录暂时无出血，区间仍表示这次经期的整体起止。

## 6. 预测与阶段的用户展示

### 6.1 月经开始

| 有效周期数 | 输出 |
|---|---|
| 0 | 记录引导；没有个人日期估计 |
| 1～3 | 历史均值估计日期与固定 7 天窗口；没有数值概率 |
| 4～5 | 日期、窗口及估计概率；说明样本较少 |
| 6～11 | 日期、窗口及估计概率 |
| 至少 12 | 使用最近 12 个有效周期 |

一个有效周期需要两个开始日期。至少 4 个有效周期通常需要 5 次连续有效经期记录。

示例结构：

> 预计 11 月 6 日开始  
> 可能在 11 月 3 日—9 日之间  
> 此窗口的统计估计概率：86%  
> 根据最近 8 个有效周期计算

日期和百分比来自真实计算。窗口固定为中心日期前后 3 天，不为展示更高概率而扩大窗口。概率旁提供可展开说明，介绍它是统计模型的估计，并非已经验证的个人准确率。

周期经过较长记录中断时提示「记录曾中断，当前估计可能与近期情况有差异」，保留断点前可用样本，不人为调整概率百分比。提醒以最新锚点标记有漏记且后续尚未形成 4 个连续有效周期为默认规则。

### 6.2 经期结束

使用最近 6 次已结束经期的持续天数中位数。持续天数为结束减开始加 1。

- 当前进行中经期：由实际开始日加估计持续天数减 1 得到预计结束日。
- 下次经期：由预计开始日得到预计结束日。
- 没有完整经期：不显示个人结束日期。
- 只有 1～2 次完整记录：说明是粗略估计。
- 预计结束日已过但结束未记录：提示补充实际结束日期，不自动闭合经期。

### 6.3 排卵、易孕及阶段

程序估计阶段，用户记录表单不提供阶段选择。

- 已记录经期优先于任何推算。
- 至少 4 个有效周期时，由月经日期分布和群体黄体期分布推算排卵日期分布。
- 1～3 个有效周期时，可用预计下次月经减约 12 天给出粗略参考日期，不显示排卵概率或概率深浅。
- 没有周期数据、参考日期无法落在当前周期内，或最新月经后存在尚未明确的不确定出血时，不给出当前阶段及排卵估计。
- 月经预测窗口已过且用户尚未核实记录时，当前阶段显示暂不能确定；保留原有估计供查看，不继续把今天归入某个阶段。
- 有经期结束记录时，结束后至估计排卵附近为卵泡期参考；排卵附近采用峰值日期前后 1 天的展示区间，之后至下次月经为黄体期参考。
- 结束未知且预计结束日已过时，优先核实经期结束，不用推算把用户归入黄体期。

卵泡期在生理上包含月经阶段；界面将月经期单列，便于理解和记录。展示分界是日历解释方式，不代表检测确认。

易孕窗口以估计排卵峰值日前 5 天至当天作为示意范围。拥有概率分布时，日历深浅表达每天属于估计易孕窗口的相对可能性，不给出怀孕概率，不使用「安全日」标记。

### 6.4 逾期及明确确认

预测窗口已过而没有新经期记录：显示「请核实记录」，保留原预测，不因未填写而自动推迟。

用户可以记录「截至某日期结束时，下一次月经仍未开始」。当日尚未结束时可以确认截至昨日；这样证据与按完整日计算的条件公式一致。该确认是事实记录，不是每日自动更新的默认状态。

明确确认后重新计算尚未发生部分的条件分布，选择未来概率最高的日期及其前后 3 天窗口。仍标注固定窗口的实际估计概率。

若只有均值估计而没有概率分布，显示已经确认的事实和「数据不足，暂不能更新日期估计」，不强行生成一个后移日期。

补录与确认日期相冲突的月经时，要求核实该确认；新周期开始后旧周期的确认不再约束新预测。确认日期之前的日期概率为零，新窗口可因此少于 7 个有非零概率的日期，但仍保留 7 个日历日的展示范围。

## 7. 统计与变化观察

### 7.1 指标定义

| 指标 | 计算方式 | 展示要求 |
|---|---|---|
| 平均周期 | 所选范围内有效周期均值 | 标明样本数 |
| 周期波动 | 至少 2 个有效周期的样本标准差 | 显示天数及「越大表示记录间差异越大」 |
| 周期趋势 | 各有效周期长度按时间排列 | 漏记间隔不画成实际长周期 |
| 周期范围 | 最短、最长有效周期 | 同所选范围 |
| 经期长度 | 各完整经期长度及中位数 | 未结束记录不参与 |
| 出血量 | 各等级的记录天数及每次经期分布 | 不换算为毫升或总失血量 |
| 颜色 | 各类别出现天数、周期日位置 | 不计算平均颜色 |
| 疼痛 | 已填自评分趋势、周期日分布 | 未填不作为 0 分 |
| 症状与情绪 | 已填写日中的类别出现比例 | 明确分母和记录覆盖 |
| 睡眠 | 已填写日时长均值、质量类别分布 | 缺失不计为 0 小时 |
| 便便 | 已填日次数、便型分布及不适 | 未记录日不计为没有排便 |
| 爱爱 | 已记录事件及不适次数 | 未记录日不计为没有事件 |
| 白带 | 已填写日的量、颜色、质地、症状类别 | 「无」与未记录分开 |

周期统计和预测可使用不同窗口：观察页按用户选定范围展示，预测始终使用最近最多 12 个有效周期，标签明确区分。

### 7.2 文字观察

周期变化的默认比较为最近 3 个有效周期与此前 3 个，需要至少 6 个有效周期；经期长度采用同样的 3 对 3 比较。每日状态比较相邻两个 30 天窗口，每个窗口至少有 7 个填写相关字段的日期，并显示各自覆盖天数。阈值用于控制稀疏数据文案，不是医学标准。

示例：

- 「最近 3 个周期比此前 3 个平均长 2 天。」
- 「最近两次完整经期中，记录为多量的天数分别为 2 天和 3 天。」
- 「已记录的疼痛更多出现在经期前两天。」
- 「这个月有 10 天填写了白带情况，其中 3 天记录为可拉丝。」

没有足够样本时展示图表和记录，不生成比较结论。变化不自动解释为疾病，不用爱爱或情绪记录断言周期变化的原因。

## 8. 知识陪伴

### 8.1 内容组织

知识随静态资源发布，每张卡片包含：标识、标题、摘要、正文、适用主题／阶段、建议、需要关注的情况、来源和审核日期。

主题包括：月经期照护、周期与波动、卵泡期与黄体期的一般变化、排卵估计、出血量和颜色、疼痛、睡眠与情绪、便便与周期、爱爱与不适、白带观察、如何记录。

### 8.2 选择规则

1. 已记录经期时选择经期照护。
2. 阶段可估计时选择对应的阶段知识。
3. 当日已填写症状时补充相应主题。
4. 记录不足或事实待核实时选择一般照护和记录方法。
5. 阶段或症状内容存在多篇时，按日期确定轮换顺序，让同一天重复进入保持一致。

症状主题卡片以单个主题为主，多个症状按预设顺序选择，不把标签组合成诊断。

### 8.3 表达与交互

卡片点击展开／收起，完整内容可进入知识详情页。用户可从卡片进入当天记录，但反馈不用于推断生理事实。

陪伴文案示例：

> 如果你这几天感觉更容易疲劳，可以给今天留一点缓冲。先记录实际感受，再决定怎样安排活动。

阶段预计剩余天数仅在边界可估计时显示为大致范围，并与下一个可能阶段一起解释。阶段未知时使用不依赖阶段的知识。

出现持续明显不适、异常出血或白带伴随明显异味及疼痛等已记录情况时，可展示适合该主题的医疗求助提示。具体健康提示由经审核的知识内容定义，提供来源。

## 11. 数据模型

本节定义逻辑模型与约束，数据库实现使用独立应用表。使用一个数据库服务一个使用者，不设计成员、共享或多用户权限表。

### 11.1 经期 `periods`

| 字段 | 含义 |
|---|---|
| id | 稳定记录标识 |
| start_date | YYYY-MM-DD，真实开始日，唯一 |
| end_date | YYYY-MM-DD 或空，真实最后出血日 |
| gap_before | 布尔值，本次与前一次之间是否漏记 |
| note | 可选备注 |
| source | USER／IMPORT |
| created_at、updated_at | 记录写入时间 |

本表只保存已确认自然月经。日常点滴或不确定出血保存在每日记录中。

数据库约束包括开始日唯一、结束不早于开始；INSERT 和 UPDATE 的区间检查触发器阻止重叠，并将结束未知视为延伸至未来的开放区间。唯一的开放区间必须在最后；修改区间也经过相同检查。客户端校验用于友好提示，数据库约束用于保证事实结构。

### 11.2 每日记录 `daily_logs`

| 字段组 | 含义 |
|---|---|
| date | YYYY-MM-DD，主键，每日最多一条 |
| bleeding_type | 空／NONE／MENSTRUATION／SPOTTING／UNKNOWN |
| flow_level、blood_colors | 可选等级及颜色列表 |
| pain_score、pain_locations | 自评分及位置列表 |
| symptoms、moods | 可空的已选标签列表；空列表表示明确无相关项 |
| sleep_hours、sleep_quality | 睡眠记录 |
| bowel_events | 可空的排便事件数组，每项含便型及感受 |
| intimacy_events | 可空的爱爱事件数组，每项含保护措施及不适 |
| discharge | 可空对象，含是否有及观察属性 |
| note | 自由备注 |
| created_at、updated_at | 写入时间 |

列表和对象使用结构化 JSON 保存，字段枚举与数值范围统一定义。月经类型的日记录必须有所属经期；经期范围本身也能表达已确认月经，用户不必逐日填写。

`NONE` 表示明确记录当天无出血，与空值不同。经期内缺少当日流量记录仍是已记录经期，但不产生某个流量等级。

### 11.3 尚未来经确认 `absence_confirmations`

| 字段 | 含义 |
|---|---|
| id | 标识 |
| anchor_period_id | 针对哪个已记录周期 |
| through_date | 确认截至该日结束仍未开始下次月经 |
| created_at | 实际确认时间 |

同一锚点采用最近、最晚的有效确认作为当前条件。删除或改正矛盾确认后重新计算。确认不能超过已结束的日历日期，也不能早于锚点开始日。

### 11.4 预测快照 `prediction_snapshots`

保存不可变预测内容与可更新评估结果：

- 快照标识、算法版本、生成时间、锚点经期标识及日期。
- 当时采用的经期日期、漏记事实、影响连续性的不确定出血及有效周期列表。
- 样本数、均值、标准差、有效尺度及概率参数。
- 中心日期、窗口起止、窗口估计概率或空。
- 有界日概率表、计算边界及剩余尾部概率。
- 条件更新使用的明确确认日期或空。
- 评估状态：待核实／已核实／漏记跳过／事实更正失效。
- 实际目标开始日与绝对日期误差，可空。

直接保存当时的计算输入，不另存历史摘要。原预测内容不随用户更正而覆盖；评估结果根据事实核实或失效。

只有影响周期预测的事实发生变化时才创建新快照；普通情绪或睡眠编辑不重复创建预测。

### 11.5 设置 `settings`

保存表单显示偏好及必要的数据格式标识。首发算法默认参数随应用版本固定，使用者不需要配置统计参数。

### 11.6 派生数据

周期观测、统计图表、阶段估计和个人观察由原始事实重新计算，不提供用户编辑入口。内存缓存用于页面切换，Tiana DB 是持久化事实来源。

## 12. 周期提取与异常提醒

### 12.1 自动选取有效周期

将确认经期按开始日排序，对相邻两次计算日历日差。有效周期需同时满足：

1. 两条日期有效，间隔为正数。
2. 后一条 `gap_before` 为没有。
3. 中间没有尚未确认性质的出血。

点滴出血不成为经期起点，也不阻断已确认的周期。当前预测锚点为最新确认经期，选取截至锚点的最近最多 12 个有效周期。

结束未知不妨碍开始日之间的周期统计，但不参与经期持续时间估计。异常长短周期只要事实连续且确认，就保留在统计中。

### 12.2 核实提醒

使用新间隔之前的有效周期计算中位数 M 和中位数绝对偏差 MAD。至少有 4 个历史有效周期时启用提醒：

- MAD > 0：稳健异常分数为 `0.6745 × (新间隔 − M) / MAD`，绝对值大于 3.5 时提醒。
- MAD = 0：新间隔与中位数相差至少 7 天时提醒。

提醒参数是产品启发式规则，不是医学标准。提醒不自动改变数据参与资格，不必回答才能完成保存。

## 13. 预测算法

### 13.1 默认参数

| 参数 | 值 |
|---|---|
| 历史窗口 | 最近 12 个有效周期 |
| 概率门槛 | 4 个有效周期 |
| 窗口半径 | 3 天 |
| 标准差下限 | 2 天 |
| 校准系数 | 1.0 |
| 经期长度窗口 | 最近 6 次完整经期 |
| 黄体期群体参数 | 均值 12.4 天，标准差 2.4 天 |
| 黄体期离散支持 | 6～20 天 |
| 易孕参考 | 排卵日前 5 天及当天 |
| 数值尾部容差 | 10⁻⁶，用于控制计算截断误差 |

这些值是确定性的工程基线，随算法版本记录。

### 13.2 开始日期与 Student's t 预测

最近 N 个有效周期长度为 L：

- `μ = ΣL / N`。
- `s = sqrt(Σ(L − μ)² / (N − 1))`，仅 N ≥ 2 时定义。
- `m = roundHalfUp(μ)`。
- 中心日期为锚点开始日加 m 天。

N < 4 时只输出均值日期估计。N ≥ 4 时：

- 自由度 `ν = N − 1`。
- 尺度 `a = max(s, 2) × sqrt(1 + 1/N)`。
- `F(x) = Tν((x − μ) / a)`。
- 正整数周期的归一化常数 `Z = 1 − F(0.5)`。
- `p(k) = [F(k + 0.5) − F(k − 0.5)] / Z`，k ≥ 1。
- 固定窗口概率为 `Σp(k)`，求和范围 m−3 至 m+3，只包含正整数 k。

使用可靠的数学库计算 t 分布 CDF，并对远尾采用稳定的生存函数或等价数值算法，避免直接相减损失精度。日期运算使用日历日序数，不用本地时间戳除以 24 小时。

概率图按尾部容差选择计算边界，记录截断外概率；有限图表不重新归一化成全部概率。实际日期超出已存表时，仍可由快照参数计算该日概率。

### 13.3 经期持续时间

完整经期持续天数为 `end_date − start_date + 1`，最近 6 次中位数按 half-up 取整。预计结束为真实或预测开始日加持续天数减 1。真实异常持续时间不因超过固定天数而删除。

### 13.4 排卵日期分布

周期长度 K 采用 p(k)。黄体期 H 的离散分布来自 `N(12.4, 2.4²)`：对 6～20 的每个整数取对应半天边界的 CDF 差，再在该支持内归一化得到 q(h)。

排卵日偏移 `O = K − H`。对每个有效组合要求 `0 ≤ O < K`，累计 `p(k) × q(h)`，并按有效组合总质量重新归一化。

周期长度计算范围根据剩余尾部概率自适应扩大；截断误差也需相对于有效组合质量足够小。不能直接把较短图表的剩余部分当成全部概率。

排卵峰值为离散排卵概率最高的日期，平局取较早日期。若有效组合无法稳定计算，返回无法估计，不强行截断到周期内某一天。

### 13.5 易孕参考

某日偏移 d 属于估计易孕窗口的概率为 `Σ pO(o)`，o 从 d 到 d+5。只展示当前周期开始日及之后的日历日期。

这是属于推测窗口的模型概率，不是性行为导致怀孕的概率。白带、爱爱记录用于观察，不自动转成排卵检测证据。

### 13.6 明确尚未来经后的条件更新

确认截至周期偏移 e 对应日期结束仍未开始：

`p(k | K > e) = p(k) / P(K > e)`，k > e，其余为 0。

用稳定的尾部概率计算分母，不通过少量已存日期求和近似完整尾部。新中心为剩余分布中概率最高的正整数日；窗口仍为中心前后 3 天，并按条件概率求和。

排卵及阶段估计若随此确认重新计算，仍保持「日历估计」表达，不把月经延迟等同于排卵已经确认。

## 14. 平均预测误差

用户侧唯一的预测表现指标：

`平均预测误差 = 已核实预测的绝对日期误差之和 / 已核实次数`。

采用应用实际保存、发生在目标月经开始前的预测。每个锚点只计一次，以该周期第一次可用的基础日期预测为准；1～3 个有效周期产生的日期估计也可核实。后续条件更新不重复增加样本，也不替换基础成绩。

- 目标为下一条确认经期。
- 下一条有漏记，无法确认是否真正下一次：跳过。
- 间隔有未确认出血：暂不计入，确认事实后核实。
- 快照生成时，目标月经实际已经开始：不计入。
- 修改影响快照的历史输入或锚点：标记评估失效，不改原预测；若目标尚未发生，可用更正后的首个预测建立新的待核实样本。
- 更正实际目标日期且不影响预测输入：更新该次绝对误差。
- 当前窗口已过但没有实际记录：不计为预测失败。

导入历史不生成用户预测成绩；导入的旧在线快照只有带完整输入、时间和可核实目标事实时才可恢复。没有可核实样本时显示「还没有可核实的预测记录」。

内部算法验收可执行时间顺序回放及概率校准测试，相关输出留在测试工具中。

## 15. 数据导入、导出与删除

### 15.1 JSON 备份

备份包含格式版本、导出时间、原始经期、每日记录、尚未来经确认、预测快照和设置。不含 Tiana 登录凭据或实例连接信息。

静态知识随应用发布，不进入个人备份。算法派生图表不作为原始事实导出。

### 15.2 导入

支持知己 JSON 备份与仅包含原始记录的同格式 JSON。导入流程：

1. 本地读取文件，验证格式、日期、枚举及记录间关系。
2. 预览新增、完全相同、冲突及无效记录数量。
3. 完全相同记录跳过；相同日期但内容不同，由用户选择保留现有或采用导入值。
4. 经期重叠、重复开始日、开放区间冲突必须先解决，再确认导入。
5. 核实新相邻间隔的漏记事实，以及确认记录与实际经期的关系。
6. 在同一数据库事务中应用已确认集合；失败不留下半份导入。
7. 重读事实，重新生成当前统计、阶段和预测。

恢复至空库时保留记录标识；合并导入如需改变标识，同时重映射确认记录和快照引用。缺少可核实事实的快照不进入平均误差。预测输入来自导出时的不可变快照，不用今天的数据补写成过去的预测。

导入事务使用同一次数据库会话，不跨独立请求拆分事务。发布前实际验证所用 Tiana SQL 协议的事务能力。

### 15.3 CSV 导出

提供便于个人查看的经期及每日记录 CSV；排便、爱爱事件可分别导出为事件明细，保留所属日期。CSV 明确区分空白与显式无／零，不把嵌套信息丢弃后称为完整备份。

### 15.4 删除

删除个人数据前说明范围并请求确认；可先导出备份。一次清除原始记录、尚未来经确认、预测快照及个人偏好，重置内存状态。删除应用内记录不删除 Tiana 实例或源码。

## 16. 前端架构与数据更新

### 16.1 模块职责

| 模块 | 职责 |
|---|---|
| 日历与记录表单 | 输入事实、显示冲突、维护当前编辑内容 |
| 数据访问 | Tiana 运行时连接、参数化 SQL、结果解析和事务 |
| 事实规则 | 日期、经期区间、每日分类和漏记关系校验 |
| 周期提取 | 从原始记录构造有效间隔 |
| 预测引擎 | 月经、持续时间、排卵、易孕及条件更新 |
| 统计引擎 | 指标、覆盖情况及变化比较 |
| 知识选择 | 按日期、阶段和主题选择静态卡片 |
| 预测核实 | 保存快照、核实目标、计算平均绝对误差 |
| 导入导出 | 文件解析、预览、事实合并和个人文件生成 |

预测函数不依赖 DOM 或网络，可通过确定性单元测试验证。

### 16.2 加载与保存

首屏优先读取经期、影响预测的出血事实、有效确认及当天记录。身体图表所需每日状态按当前范围加载，邻近日期和页面复用内存缓存。

保存过程：校验输入 → 同一事务保存有关事实 → 重读已保存结果 → 重算派生数据 → 必要时保存新的预测快照 → 更新页面。

保存中禁用重复提交，提交前确定记录标识。响应丢失或写入结果未知时，先用独立只读查询核实该标识和内容，不自动重放写入。表单保持用户输入，并用文字说明正在保存、已经保存、保存失败或正在核实。

原始记录已保存但快照保存失败时，记录仍可见，预测照常计算；恢复连接后核实并补存当前快照。快照生成时间使用实际生成时间，不能回填成目标发生前的在线预测。

离线时已有页面可继续查看；未提交输入保留在当前编辑页面内，恢复网络后再保存。云端是持久化来源，页面关闭前有未保存内容时提示用户。运行时凭据不进入数据库、导出文件或浏览器持久化缓存。

## 18. 验收范围

### 18.1 事实与日历

- 相同开始日期重复写入被数据库拒绝。
- 完整、开放区间的新增和修改均不能造成重叠。
- 结束早于开始、未来事实日期不能保存。
- 跨月、跨年、闰日以及存在夏令时的日期差均正确。
- 同一日编辑更新原记录；每日未知、无和有分别保留。
- 补录和删除后的漏记关系正确，不将已知缺失变成长周期。
- 点滴不重置周期，不确定出血阻断相应间隔。

### 18.2 数学计算

- 已知序列的均值、标准差、half-up、中位数和含首尾持续天数正确。
- 漏记示例中 28、28、83、28、28 只采用四个 28。
- 0 个有效周期无日期预测，1～3 个无数值概率，4 个启用概率。
- 相同长度记录使用 2 天波动下限，不生成 100% 确定性。
- 离散概率、截断尾部及固定窗口与 CDF 计算一致。
- 排卵分布只包含有效组合，尾部截断满足容差。
- 易孕日概率符合排卵日前 5 天及当天定义。
- 未确认尚未来经时结果不自动后移；明确确认后已排除日期为零概率。
- 改动事实后当前结果更新，旧快照内容不变。

### 18.3 预测表现与统计

- 同一锚点不因打开页面或条件更新重复计入误差。
- 漏记、事实更正及预测生成晚于目标实际开始的样本不计入。
- 导入历史不会生成过去的在线预测成绩。
- 统计采用真实填写值，缺失不变成无或零。
- 每条变化文字的数值、范围和样本可由记录追溯。

### 18.4 持久化与导入导出

- 在真实 Tiana DB 写入后刷新，记录仍存在。
- 同一身份的手机和桌面读取相同事实。
- 网络中断或响应缺失后核实保存状态，不制造重复记录。
- JSON 导出再导入空库，原始记录及关系一致。
- 冲突不静默覆盖，导入失败不产生部分数据。
- 删除后原始记录与预测快照均不存在。

### 18.5 界面与知识

- 手机窄屏无主要内容横向溢出，桌面日历与图表可正常操作。
- 键盘可完成日期选择、表单提交及知识卡片展开／收起。
- 实际记录与估计的图例清晰，阶段不需要手动选择。
- 首页文案与当前记录状态相符，阶段不明时使用一般知识。
- 用户预测表现只有平均预测误差。

## 19. 健康边界与已知限制

- 产品适用于自然月经周期记录。怀孕、产后恢复、激素类药物影响及其他改变周期机制的情况，日历模型不适用。
- 月经日期概率依赖个人历史和统计假设，默认参数不是临床验证结果。
- 排卵和易孕日期使用群体黄体期参数及近似独立假设，不能确认排卵、判断安全日或提供避孕保证。
- 未填写不能证明某事件没有发生。应用只能依据实际记录和明确确认更新判断。
- 出血量是主观等级，颜色、便型、白带和症状是观察事实，不能独立用于诊断。
- 平均预测误差仅反映少量已核实日期估计的偏差，不证明模型概率已经校准。
- 静态知识根据记录选择内容，不能完成个体诊断或实时医疗评估；明显或持续不适应寻求专业医疗帮助。
- 云端读写依赖网络和 Tiana 会话，当前页面未保存内容不等同于已备份。
