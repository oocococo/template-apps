    它认得哪些东西

    一共八类。每一类都不是"能打开就行"，而是要把文件自己说的话读出来。

    图片

    尺寸、百万像素、色深、DPI，以及完整的 EXIF：机身、镜头、曝光、方向、GPS 坐标。

    jpg jpeg png gif webp avif bmp ico svg

    多页 TIFF

    每个 IFD 就是一页，扫描件一次进十二张也能当一个文档翻。支持 LZW、Deflate、PackBits。

    tif tiff

    PDF

    逐页渲染：纸张尺寸（pt 与 A4/Letter）、PDF 版本、生成工具、创建时间、总页数。

    pdf

    Office 三件套

    Word 的分节、表格的每个工作表、演示文稿的每张幻灯片，都对应一个真实的"页"。

    docx xlsx pptx

    文本与表格

    编码是测出来的，不是猜的（UTF-8 / UTF-16 / GBK / Windows-1252）；CSV 按它真正用的分隔符变成表格。

    txt csv tsv json md log xml

    裸 YUV 帧

    安卓相机 onPreviewFrame 或 ImageReader 直接吐出来的数据：没有文件头、没有尺寸。选对排布，画面和帧数自己就出来了。

    yuv nv21 nv12 i420 yv12

    视频与音频

    时长、分辨率、宽高比从容器里读，画面交给浏览器自己的解码器。

    mp4 webm mov m4v mp3 wav ogg

    其它一切

    二进制不画假预览：认出容器就报容器，认不出就说认不出，绝不糊一张占位图冒充内容。

    exe zip sqlite elf …

    为什么"元数据"才是救命的那一半

    管线出问题的时候，文件往往比画面更早说出原因。

    一张 JPEG 写着 orientation 6，说明它拍的时候是横着拿的；忽略 EXIF 的解码器会把一个躺倒的画面 送进 OCR，识别率自然崩。一个 TIFF 的页数是 1，可进纸器明明吞了十二张——那是在上游就被截断了。 一个 PDF 没有 Producer、创建日期停在 2001 年，它是被"压平"过的扫描件，不是导出的文档。

    裸 YUV 是最能说明问题的例子。安卓相机 dump 出来的文件没有头：没有宽、没有高、没有像素格式， 也不知道里面是一帧还是四十帧。这里会先拿文件长度去对常见采集尺寸，猜一个；然后让你改： 选 NV21 / NV12 / I420 / YV12 / YUY2 / UYVY，填宽高和 stride，帧数和颜色立刻归位。 4:2:0 排布选错不会报错，只会让画面变成绿色和紫色——那正好就是你要找的那个 bug。

    • 类型先看文件头，后缀只作参考：一个 .jpg 其实是 PNG，这里就写 PNG，并且当场提示"后缀与内容不符"。
    • SHA-256 用 Web Crypto 在本地算，两份文件对不对得上，不用把它们传到任何地方。
    • 页码按文件真实结构走，解析器按需加载：打开一张图，不会顺手下载一个 PDF 引擎。

    它不做什么

    把边界写在前面，比事后解释便宜。

    Office 渲染是"重建"，不是排版引擎：字体被替换、复杂版式会重排、SmartArt 和图表会留下空框。 Word 的页来自文档自己的分节和分页符，所以依赖"缩小以适应页面"的文档在这里可能分得不一样； Excel 每 40 行切一页，是为了让翻页键在一万行的表里还有意义，不是工作簿自己的打印版式。

    视频能不能播，完全取决于浏览器的解码器：.mov 里装 H.265，时长读得出来，画面未必放得动。 TIFF 解码覆盖常见压缩，冷门变体不保证。裸 YUV 按定义就没有元数据，第一帧在你填宽高之前都是猜的。 这里也不是取证工具：它只报告字节说了什么，SHA-256 算的是你拖进来的那一份。

    大文件：PDF 超过 150 MB、文本超过 8 MB、Office 超过 60 MB 会被截断或拒绝，并在预览区注明原因—— 浏览器标签页不是十六进制编辑器。
