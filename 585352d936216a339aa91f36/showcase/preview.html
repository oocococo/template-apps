使用说明

三步拿到一份能直接写进周报的工作记录

01
复制命令

在仓库根目录执行，把整段输出复制下来。三选一，按需要的精度挑。

git log --pretty=format:'%h|%ad|%an|%s' --date=short
git log --pretty=format:'%h|%ad|%an|%s' --date=format:'%Y-%m-%d %H:%M'
git log --since="2026-10-01" --pretty=format:'%h|%ad|%an|%s' --date=short

第二条带时间，能看小时级分布；第三条限定时间范围，适合按季度取数。

02
粘贴解析

贴进上方输入框，点「开始降噪」，或按 Ctrl+Enter。也可以直接导入 .txt / .log 文件。

不挑格式，下面这些都能读：

  • a1b2c3d|2026-10-14|dev-a|feat: xxx管道
  • 2026-10-14 dev-a feat: xxx空格
  • a1b2c3d feat: xxxoneline
  • commit / Author: / Date:完整多行
03
导出总结

切到「导出总结」，拿到按日期分节的 Markdown。三种取用方式：

  • 复制 Markdown贴周报
  • 复制纯净列表只留 commit
  • 下载 .md存归档

导出只含真实提交，噪音不进结果；作者名默认已脱敏。

降噪规则

按提交信息文本判定，不需要读 diff

类别 命中特征 温和 标准 / 严格
构建部署build: ci: 部署 / 上线 / 更正式 / 更新X环境过滤过滤
合并提交Merge / 合并保留过滤
版本号纯版本号 / bump / chore(release)保留过滤
回滚Revert / 回滚 / 撤销保留过滤
文档docs: / 文档 / readme保留仅严格过滤
真实开发其余全部（feat / fix / refactor / perf…）保留保留
按季度取数

填绩效或述职时，用 --since 把范围限定在本季度，噪音占比和真实提交数就是这一季的实际值。

作者脱敏

默认开启，作者名按出现顺序替换为 dev-01、dev-02。导出的记录常要贴进周报或对外文档，真实姓名不该跟着走。需要核对时再关掉。

数据不出本机

全部解析在浏览器内完成，零网络请求。这个页面可以直接断网使用，也能存到本地随时打开。

分类的边界

规则看的是提交信息，不解析 diff。团队若完全不写规范（全是"修改""提交"），分类会失准——但这类提交本来也写不进周报。
