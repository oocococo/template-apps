# 卡带俱乐部 · 红白机模拟器加载器

上传自己的 `.nes` ROM，放进游戏库，在浏览器中游玩。ROM 保存在 Tiana 文件存储；SQLite 保存游戏目录及每款游戏的三个即时存档槽。刷新或重新打开应用时，自动加载上次成功打开的卡带并保持暂停，可点击开始或读取存档。SQLite 按应用记住卡带哈希和文件相对路径，存档内容保存在文件存储；带卡带哈希的链接优先加载链接指定的游戏。自动加载不增加使用次数，删除卡带时清除对应的云端设置。

## 操作

| 按键 | 动作 |
| --- | --- |
| A / D / W / S | 左 / 右 / 上 / 下 |
| Tab | SELECT（选择） |
| 空格 / Enter | START（开始、确认） |
| J | A，按住连发 |
| K | B，按住连发 |
| N | 普通 A，按住保持按下 |
| M | 普通 B，按住保持按下 |
| Esc | 暂停，释放所有按键 |

实际 A/B 动作由游戏决定。J/K 使用 JSNES 的逐帧 Turbo，N/M 不连发，可用于蓄力、持续加速和长跳等操作；窗口失焦、页面隐藏、暂停、读取存档及切换卡带时释放所有输入。键盘游戏操作在开始后生效；暂停后 Tab 可正常浏览页面控件。手机提供同样的方向、选择、确认和连续动作触控按钮。

暂停时保留游戏当前画面，在画面上叠加半透明的「已暂停」提示和继续按钮。

手机默认使用八方向摇杆，也可切换为八方向方向键。摇杆中心约移动 7 像素即可触发，回到更小的中心区域时松开；方向边界保留小幅容差，减少拇指晃动造成的来回换向。A/B 区域支持按住后滑动换键，滑出按钮松开、滑回重新按下，多根手指独立控制。需要持续跳跃或蓄力时使用普通 A/B，连发键仍按原键位保留。左拇指拖动可连续改变方向并斜向移动，右手可同时按 A/B 连发或普通 A/B。摇杆中心为松开区域，松手、触摸取消、切换控制方式、旋转屏幕、页面滚动或暂停时释放触屏输入。触屏控制区域内不会拖动页面，区域外仍可正常滚动。手机横屏且已加载卡带时自动进入铺满页面的游戏视图，摇杆在左下角、A/B 在右下角半透明悬浮，「选择」「开始」在横屏时自动隐藏，转回竖屏后显示，暂停和退出全屏在右上角。画面保持原比例，手柄不再占用单独一列。点击「退出全屏」可返回游戏库。手动进入全屏后，横竖屏切换保持全屏：横屏控件悬浮，竖屏控件排列在画面下方，游戏进度保留。仅由横屏自动进入的游戏视图，转回竖屏时恢复普通页面。微信等内置浏览器如果保持竖屏，可点击「横屏」在页面内旋转整个游戏画面和悬浮手柄；摇杆方向随画面转换，支持边移动边按键。点击「自动转屏」恢复跟随浏览器方向，退出全屏也会清除手动横屏。点击「全屏」时同时请求浏览器全屏，浏览器无法进入原生全屏时仍可使用铺满页面的游戏视图。

点击「保存进度」将当前模拟器状态和缩略图保存到所选槽位；「覆盖保存」替换该槽位；点击「读取」恢复并继续游玩。存档是手动操作。以 ROM 内容的 SHA-256 区分游戏，相同文件改名上传仍使用原来的卡带及存档。游戏和存档按 Web 应用隔离，同一应用中的成员共享。

删除卡带前会显示确认提示，同时删除 ROM 文件、该游戏的全部存档和目录记录。文件或记录已经不存在时按成功处理，重复删除可安全重试。文件删除成功后才清理存档，最后删除目录；服务或网络失败时显示错误，并保留尚未完成的目录记录供重试。

## 创建应用

1. 创建本次应用的 Tiana SQLite 和 Git 实例，将 `source.json` 的两个绑定填为实际 ID。模板安装时按 `metadata.json` 替换完整占位符。
2. 使用该 SQLite 实例执行 `schema.sql`。本工程没有 seeds。
3. 安装依赖：`npm ci --ignore-scripts`。运行 `npm test` 验证存档恢复、键位和八方向输入，`npm run test:browser` 验证暂停画面和手机多点触摸（首次使用需 `npx playwright install chromium webkit`）。
4. 把完整源码提交、推送至 Tiana Git，核对远端 commit。运行 `npm run build -- <完整源码commit>`，构建输出在 `dist/`，`TIANA_PROJECT_PARAMS` 输出数据库与 Git 绑定。
5. 用 `tiana web create` 创建应用，指定固定入口 `app.js` 及两项实例绑定，保存其 Web ID。用 `tiana web serve WEB_ID --dir dist` 预览，或 `tiana web publish WEB_ID --dir dist --json` 发布并核验 `tiana web status`。
6. 在页面中上传 `.nes`，开始游玩并保存；刷新页面，再读取存档检查持久化。

应用通过 `window.tiana.connection()`、`window.tiana.auth` 访问 SQLite，通过 `window.tiana.files` 上传和下载 ROM，需要提供这三项能力的 Tiana Web 运行环境。使用文件存储 API，无需把 ROM 编入 Web 构建产物。

## 数据与定制

- `nes_games`：按应用和 ROM 哈希保存名称、文件相对路径、大小及上传时间。游戏库按置顶优先、成功加载次数从高到低排序，同次数按上传时间从新到旧、ROM 哈希降序稳定排列。点击卡带的「置顶 / 取消置顶」可更改状态；置顶组内仍按使用频率排序。主动选卡或上传后成功加载计一次，刷新页面恢复卡带、暂停和继续不增加次数。使用次数与置顶状态保存在 SQLite。游戏库在独立滚动区域中每次加载 25 条，用户点击「更多卡带」继续读取。搜索名称时查询 SQLite 中本应用的全部游戏，按名称子串匹配；不会列举文件存储。卡带「改名」只更新显示名称，保持 ROM 路径和存档关联。
- `nes_save_slots`：按应用、ROM 哈希和槽位保存模拟器快照、画面缩略图的文件相对路径及时间；只读取当前游戏的存档。
- `src/controls.js` 维护键位，`src/style.css` 维护界面，`src/storage.js` 维护参数化 SQL。
- `build.mjs` 从固定 JSNES 依赖提取独立 AudioWorklet，并以相对资源路径加载。
- `public/icon.png` 是默认应用图标，构建时原样复制到 `dist/icon.png`，随发布包注入应用管理图标。替换源图片后重新构建、发布即可更新；每次发布都会使用工程中的图片覆盖当前管理图标。

上传或存档报错时先刷新相应列表核对结果；ROM 文件上传与 SQLite 目录写入是两个步骤，目录写入未确认时文件可能已存在，可在文件存储中核对。文件目录由应用的 Web ID 决定。

支持 JSNES 2.1.0 能运行的 NES/iNES 卡带，并增加 Mapper 25（Konami VRC4b/VRC4d）的程序和图形换页、IRQ 及即时存档。不支持的 Mapper 在上传控件旁显示具体编号，不会占用文件存储。游戏库没有三款游戏或 1 MB 的应用限制。

模板从空游戏库开始，不附带 ROM，使用者自行上传游戏。本工程测试使用自编诊断程序，第三方依赖见 `THIRD_PARTY_NOTICES.txt`。
