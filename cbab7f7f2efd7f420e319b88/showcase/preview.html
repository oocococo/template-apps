🧠 算法原理
1️⃣ Unicode 码点映射
每个字符通过 charCodeAt() 映射为 Unicode 码点数值，然后使用 BigInt LSB 算法编码到图像像素中。解码时读取 LSB 位还原码点数值，再通过 String.fromCodePoint() 还原原始字符。

支持的字符范围：
  • 数字：0-9（码点 48-57）
  • 大写字母：A-Z（码点 65-90）
  • 小写字母：a-z（码点 97-122）
  • 常用标点：!@#$%^&*() 等（码点 33-47, 58-64 等）
  • 空格、换行、制表符等
  • 中文字符（码点 0x4E00-0x9FFF 范围）
  • 理论上支持任何 Unicode 字符
'A' → 码点 65 → BigInt(65) → 7bit 二进制 → 嵌入像素 LSB
'a' → 码点 97 → BigInt(97) → 7bit 二进制 → 嵌入像素 LSB
'!' → 码点 33 → BigInt(33) → 6bit 二进制 → 嵌入像素 LSB
'中' → 码点 20013 → BigInt(20013) → 15bit → 嵌入像素 LSB
2️⃣ LSB 隐写编码（BigInt 安全）
将每个码点转换为二进制位流。在载体图像的每个像素中，RGB 三通道各占用 1 个最低有效位（LSB），每个像素可携带 3 bit 数据。 全程使用 BigInt 位运算，突破 JavaScript 32位位移限制，支持任意大码点值。
BigInt(v) >> BigInt(i) & 1n → 安全提取任意位宽的每一位
像素(R,G,B) → (R&0xFE|bit1, G&0xFE|bit2, B&0xFE|bit3)
每像素 3 bit，256×256 图像可存储 ≈ 24,576 bit
3️⃣ 数据头部格式
编码数据前 32 bit 为头部：前 16 bit 表示数据项个数 N，后 16 bit 表示位宽 W。 W=0 为加密模式魔数值，表示数据区为 AES-256 加密后的字节流（每字节 8bit）。 W≥1 为明文模式，每个码点用 W bit 定长编码。
明文: [16bit: count=N] [16bit: width=W≥1] [N × Wbit: codepoints]
加密: [16bit: count=N] [16bit: width=0] [N × 8bit: salt(16B)+IV(12B)+ciphertext]
4️⃣ AES-256 加密层（可选）
设置密码后，文本先经 UTF-8 编码为字节，再使用 AES-GCM-256 加密。 密钥通过 PBKDF2-SHA256（100,000 次迭代）从用户密码派生。 加密后的字节流（含随机 salt + IV + 密文 + 认证标签）嵌入图像 LSB。

安全性：无密码无法解密；错误密码会被 AES-GCM 认证标签拒绝（不会输出乱码）。 每次编码使用不同的随机 salt 和 IV，即使相同文本和密码也会产生不同的密文。
password → PBKDF2(100K iterations, SHA-256) → 256-bit key
text → UTF-8 → AES-GCM-256(key, random IV) → ciphertext
[salt(16B) + IV(12B) + ciphertext] → bytes → 8bit each → LSB embed
